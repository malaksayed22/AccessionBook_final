# Strict Style-Only Edits

The user has strict edit rules. Mistakes are possible, so check every change against this list before and after editing.

## Allowed (styles and layout only)

- CSS, Tailwind classes, inline styles, CSS variables, design tokens
- Layout: flex/grid, spacing, sizing, alignment, positioning, responsive breakpoints, ordering of elements purely for visual layout
- Visual styling: colors, fonts (family, size, weight, line-height, letter-spacing), borders, radius, shadows, backgrounds
- Visual-only motion: transitions and animations that do not alter behavior

## Forbidden (never change)

- **Logic**: state, hooks, effects, handlers, conditions, loops, data fetching, routing, props contract, function bodies, imports that alter behavior
- **Words**: any text content, labels, headings, button text, placeholders, alt text, aria-labels, titles, error messages, translations. No rewording, fixing typos, rephrasing, adding or removing copy.
- **Data**: values, arrays, objects, constants, API calls, content files
- **Structure that carries meaning**: do not remove, add, or reorder elements/components in a way that changes content or behavior. Wrapper elements for layout are allowed only if they add no text and no logic.

## Process

1. Before editing, state which files and which style/layout lines will change.
2. Make the smallest style/layout-only change that achieves the request.
3. After editing, re-read the diff. Confirm no text, logic, or data line was touched. If one was, revert it.
4. If a request seems to require a logic or wording change, STOP and ask the user instead of doing it.
5. Report exactly what was changed (style/layout only) and flag anything left untouched on purpose.
